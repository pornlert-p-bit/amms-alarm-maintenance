## ช่องโหว่ที่พบและแก้

| # | ช่องโหว่ | ผลกระทบ | การแก้ |
|---|---|---|---|
| 1 | RLS ให้ staff UPDATE ตาราง alarms ได้ทุกคอลัมน์ — กฎลำดับสถานะและผู้ปิดอยู่แค่ใน Server Action | technician ยิง API ตรงเพื่อแก้ Alarm ที่ปิดแล้ว ย้อนสถานะ หรือปลอมผู้ปิดได้ | migration 003: trigger ก่อน UPDATE (บันทึกเหตุผลใน ADR-003 Revision) |
| 2 | trigger ของ migration 003 ครอบคลุมเฉพาะ UPDATE ไม่ครอบคลุม INSERT | สร้าง Alarm ที่ "ปิดแล้ว" พร้อมปลอมผู้บันทึก/ผู้ปิดได้ | migration 004: trigger ก่อน INSERT |

**บทเรียน:** การมี RLS ไม่ได้แปลว่าทุกคอลัมน์ปลอดภัย — RLS คุมว่า "ใครแตะแถวไหนได้" แต่ไม่ได้คุมว่า "แก้คอลัมน์ไหนเป็นค่าอะไรได้" กฎของข้อมูลที่ห้ามปลอมต้องบังคับด้วย constraint หรือ trigger เพิ่มอีกชั้น
